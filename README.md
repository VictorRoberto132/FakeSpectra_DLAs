# FakeSpectra_DLAs

Synthetic Lyman-alpha absorption spectra around IllustrisTNG haloes, with the
absorption decomposed into a **High Column Density (HCD)** component and the
surrounding **Lyman-alpha forest**.

For every halo in a mass-stratified sample, sightlines ("skewers") are shot
through the simulation box at a range of impact parameters `b` in units of the
halo `R_200`. Along each sightline the code identifies the HCD structure with a
1D region-growing algorithm and interpolates *only* those gas cells, so the
resulting spectrum contains the absorption that belongs to the halo and not the
unrelated forest that happens to lie along the line of sight.

This repository holds the driver, the analysis modules and the notebooks. The
modified `fake_spectra` lives in a separate fork (see
[Installation](#installation)); the data products are not versioned and are
regenerated by running the pipeline.

## The physics in one page

**Two thresholds, which are easy to confuse.**

| | Value | Applied to | Purpose |
|---|---|---|---|
| **Seed** | log N_HI = 16.5 | individual gas cells | nucleates the region growing |
| **Selection** | log N_HI = 17.2 | the integrated sightline column | keeps only real HCDs |

The seed is deliberately *below* the observational HCD definition. It is
obtained by inverting the Schaye (2001) Jeans-length column-density relation
combined with the Rahmati et al. (2012) self-shielding prescription, at the
snapshot redshift. Seeding conservatively means the grown structure cannot clip
a genuine HCD; the strict cut is applied afterwards, to the integrated column.

**The three stages of the decomposition**, per sightline:

1. **Seed** — flag every cell whose neutral hydrogen density exceeds the seed
   threshold, after attenuating by the SPH/Voronoi kernel weight at the cell's
   perpendicular distance from the sightline.
2. **Grow** — from each seed, grow a 1D region along the line of sight while the
   total hydrogen density stays above an envelope threshold, tolerating gaps of
   up to a few cells. A kernel-bleed cleanup then absorbs cells whose smoothing
   length overlaps the grown block.
3. **Localise** — accept only cores that fall within `± halo_radius_cut * R_200`
   of the halo centre along the line of sight (default 5). Secondary systems
   intersected by chance are rejected and bleed into the forest channel instead.

Cells surviving the mask are handed to the C interpolator; everything else is
dropped. A sightline whose integrated column then fails the 17.2 cut is zeroed
(`flux = 1` everywhere, `log_n_hi = 0.0`, `is_hcd = False`) — that is a
**selection outcome**, not missing data.

**Absorber classes** used throughout the analysis, in log N_HI:

| Class | Range |
|---|---|
| `Forest` | < 17.2 |
| `LLS` | 17.2 – 19.0 |
| `Sub_DLA` | 19.0 – 20.3 |
| `Small_DLA` | 20.3 – 21.0 |
| `Large_DLA` | ≥ 21.0 |

**Decomposition modes.** `HCD_only` keeps the HCD structure, `Forest_only` keeps
its complement, `None` reproduces stock `fake_spectra` (all cells). The legacy
spellings `DLAs` and `No_DLAs` are still accepted and silently normalised.

## Installation

### 1. Environment

```bash
conda create -n fakespectra python=3.11
conda activate fakespectra
pip install numpy pandas h5py matplotlib scipy tqdm
```

A C++ compiler is required to build the extraction extension. On a bare
environment: `conda install -c conda-forge gxx_linux-64`.

### 2. The HCD fork of fake_spectra

```bash
pip install "git+https://github.com/VictorRoberto132/fake_spectra@v2.2.4-hcd1"
```

This is a fork of [sbird/fake_spectra](https://github.com/sbird/fake_spectra)
v2.2.4 (MIT), with the HCD/forest decomposition added to `spectra.py`. Nothing
else in the package was touched. To see exactly what changed:

```bash
git clone https://github.com/VictorRoberto132/fake_spectra
cd fake_spectra
git diff v2.2.4..v2.2.4-hcd1 -- fake_spectra/spectra.py
```

### 3. Verify

```bash
python -c "import inspect, fake_spectra.spectra as s; \
           print('filter_mode' in inspect.signature(s.Spectra.__init__).parameters)"
```

Must print `True`. If it prints `False`, or raises, the stock upstream package is
installed instead of the fork — `tools/utils.py` will refuse to import and tell
you the same thing.

> **Note.** Run this from anywhere *except* a directory that contains a
> `fake_spectra/` folder. Python puts the working directory first on `sys.path`,
> so a source checkout shadows the installed package and the compiled
> `_spectra_priv` extension will appear to be missing.

**Reading the output does not require the fork.** The `.pkl` files are plain
pandas, and `tools/radii_skewers.py` imports `utils` lazily, so the
post-processing helpers work on a numpy/pandas-only install.

## Getting the simulation data

The pipeline reads IllustrisTNG snapshots and FoF group catalogues directly.
Download them from <https://www.tng-project.org/data/> (registration required).

For the runs in this repository: **TNG50-2, TNG50-3 and TNG50-4, snapshot 25**
(z ≈ 3.008). Each simulation directory must contain:

```
<BASE_PATH>/
├── groups_025/
│   └── fof_subhalo_tab_025.*.hdf5     Group_M_Crit200, Group_R_Crit200,
│                                      GroupPos, GroupVel, GroupFirstSub
└── snapdir_025/
    └── snap_025.*.hdf5                PartType0: Coordinates, Masses, Density,
                                       NeutralHydrogenAbundance, Velocities
```

`BASE_PATH` is the directory containing those two folders; point the driver at
it. Full snapshots are large (TNG50-2 is several TB); TNG50-4 is the cheapest
place to start.

## Running the extraction

Everything is driven by the CONFIG block at the top of the driver.

```bash
cd instructions
# edit CONFIG: BASE_PATH, SIM_NAME, SNAP_NUM, N_RUNS, mass bins, cores, ...
python 00_run_the_pipeline_illustrisTNG.py --dry_run   # checks + prints commands
python 00_run_the_pipeline_illustrisTNG.py             # actually runs
```

The driver runs a preflight (modules present, fork installed, simulation
directories readable, core count sane, disk space), creates the output folder in
the project root, runs one realization per seed, and writes `run_config.json`
next to the data.

Useful flags:

| Flag | Effect |
|---|---|
| `--dry_run` | preflight and print the commands, extract nothing |
| `--runs 2,4` | redo only these realizations |
| `--force` | write into a folder that already holds `.pkl` files |

### Standard configuration

| Parameter | Value |
|---|---|
| Mass bins, log10(M_200/M_sun) | 10.0, 10.5, 11.0, 11.5, 12.0, 13.0 |
| Haloes per bin | 150 (bins with ≤ 100 available are taken whole) |
| Haloes per realization | 637 |
| Impact parameters | `b = 0` plus 30 log-spaced values from 0.01 to 50 R_200 |
| Skewers per halo | 363 = 3 (at b = 0) + 12 × 30 |
| Rows per realization | 231,231 |
| Pixel width | 10 km/s → `nbins = 396` for TNG50 at z = 3 |
| Realizations | 5, seeds 42 / 137 / 2025 / 999 / 31415 |

Each `b > 0` gets 12 sightlines: 4 offsets (Right, Left, Top, Bottom) × 3
line-of-sight axes (x, y, z). At `b = 0` there is one per axis.

### Cost

One snapshot read per halo, not per skewer. With `products` including `temp`
there are three passes over the chunks per halo (`get_tau`, `get_col_density`,
`get_temp`); drop `temp` to go back to two. Calibrate `SECONDS_PER_HALO` by
timing a single halo — it only affects the estimate printed at startup.

A quick end-to-end smoke test, one halo:

```bash
cd tools
python run_parallel_illustris.py --sim TNG50-4 \
    --mass_bins 11.5,12.0 --n_per_bin 1 --n_impacts 1 \
    --cores 1 --outdir /tmp/smoke_test
```

## Output format

One pickled `DataFrame` per realization. **The file is self-describing**: the
shared grids and the snapshot constants travel in `df.attrs`, which survives
`to_pickle`/`read_pickle`, so there is no sidecar file to lose.

`instructions/01_check_io_format.ipynb` walks through all of this and validates
it; the tables below are the summary.

### Columns — one row per sightline

**Scalars**

| Column | Meaning |
|---|---|
| `halo_id` | global FoF index in the group catalogue |
| `halo_mass` | `Group_M_Crit200`, code units (1e10 M_sun/h) |
| `halo_r200` | `Group_R_Crit200`, code length units (ckpc/h for TNG) |
| `halo_vmax` | `SubhaloVmax` of the central subhalo, km/s physical; NaN if none |
| `redshift` | snapshot redshift, repeated per row so runs can be concatenated |
| `skewer_id` | index of the sightline within its halo |
| `axis` | line-of-sight axis: 0 = x, 1 = y, 2 = z |
| `position_tag` | offset direction: Center / Right / Left / Top / Bottom |
| `r_multiplier` | impact parameter `b`, in units of R_200 |
| `impact_kpc` | impact parameter in ckpc/h |
| `log_n_hi` | log10 of the **integrated** N_HI [cm^-2]; exactly 0.0 below the cut |
| `is_hcd` | did the integrated column reach 10^17.2 |
| `vel_peak_shift` | velocity of the deepest trough nearest v = 0, km/s |

**Arrays** — one `float32` array of `nbins` values per row, all sampled on
`df.attrs['v_grid']`:

| Column | Meaning |
|---|---|
| `flux` | transmitted flux F = exp(−τ) |
| `n_hi_col` | HI column density per pixel [cm^-2] |
| `temp` | N_HI-weighted temperature per pixel [K]; 0 where there is no HCD gas |

With more than one decomposition mode, every per-mode column gains a `_<mode>`
suffix (`flux_HCD_only`, `log_n_hi_Forest_only`, …).

### `df.attrs` — one value per snapshot

| Key | Units / meaning |
|---|---|
| `v_grid` | km/s, halo rest frame — the x-axis of every array column |
| `wave_grid` | Angstrom, rest frame (= `lam_rest * exp(v/c)`) |
| `chi_grid` | code length units, comoving (= `v_grid / velfac`) |
| `nbins` | pixels per spectrum |
| `vmax`, `dvbin`, `velfac` | km/s box, km/s per pixel, km/s per code length unit |
| `box_size` | code length units |
| `redshift`, `lam_rest` | — |
| `pixel_length_cm` | cm, physical: `n_HI[cm^-3] = n_hi_col / pixel_length_cm` |
| `hcd_log_nhi_cut` | the sightline selection threshold (17.2) |
| `length_unit_kpc` | ckpc/h per code length unit (1.0 for TNG) |
| `modes` | decomposition modes present in the file |
| `sim_name`, `snap_num`, `run_id`, `seed` | provenance |

### What is deliberately *not* stored

Anything that is an exact function of what is already in the file was left out,
and is recomputed on demand. Storing the three spectral axes per row instead of
once in `attrs` would have added several GB of pure duplication per file.

| Not stored | Recover with |
|---|---|
| `eq_width`, `mean_vel`, `std_dev`, `skewness`, `kurtosis`, `vel_coherent`, `T_hi` | `rs.add_moments(df)` |
| `halo_v200`, `halo_c200` | `rs.add_concentration(df)` |
| `total_col_den` | `rs.total_col_den(df['log_n_hi'])`, i.e. `10**log_n_hi` |
| absorber class | `rs.categorize(df['log_n_hi'])` |
| `vel_aligned` | `df.attrs['v_grid'] - row['vel_peak_shift']` |
| n_HI in cm^-3 | `n_hi_col / df.attrs['pixel_length_cm']` |

## Reading the results

```python
import sys
import pandas as pd
sys.path.append("tools")
import radii_skewers as rs

df = pd.read_pickle("data_TNG50-2_snap025_5runs/"
                    "TNG50-2_z3_637Halos_HCDMode_Stratified_run0_seed42.pkl")
meta = dict(df.attrs)

# Derived quantities, added in place
rs.add_moments(df)          # eq_width, std_dev, skewness, kurtosis, T_hi, ...
rs.add_concentration(df)    # halo_v200, halo_c200
df["category"] = rs.categorize(df["log_n_hi"])

# One spectrum, on the shared grid
row = df[df["is_hcd"]].iloc[0]
v, F = meta["v_grid"], row["flux"]
```

A caveat worth knowing: `kurtosis` collides with the pandas `Series.kurtosis()`
method. Use `row["kurtosis"]`, never `row.kurtosis`.

`instructions/01_check_io_format.ipynb` provides `load_run(path)` and
`load_runs(directory)`, plus integrity checks and sanity plots. Start there.

## Reproducing the published runs

The `.pkl` files are not in the repository, but the recipe is. Every
`data_*/run_config.json` records the driver, the interpreter, the simulation and
snapshot, the mass bins, the impact grid, the modes, the core count, the seeds,
and the exact command line of each realization. To reproduce a set:

```bash
cat data_TNG50-2_snap025_5runs/run_config.json
```

then either replay the commands it lists verbatim, or copy those parameters into
the driver's CONFIG block and run it. The seeds are deterministic, so the same
haloes are drawn.

## The fake_spectra fork

Fork of [sbird/fake_spectra](https://github.com/sbird/fake_spectra) v2.2.4,
branch `hcd`, tagged `v2.2.4-hcd1`. Only `fake_spectra/spectra.py` differs.
What was added:

- **`filter_mode`** — `None` / `HCD_only` / `Forest_only`, with the legacy
  `DLAs` / `No_DLAs` spellings accepted and normalised.
- **Seeded region growing** — the Schaye (2001) + Rahmati et al. (2012)
  inversion for the per-particle seed column, then 1D growth with a double
  threshold, gap tolerance and kernel-bleed cleanup.
- **Halo-centric core selection** — `halo_r200` and `halo_radius_cut` restrict
  accepted cores to a window around the halo along the line of sight.
- **`get_temp` made filter-aware** — the numerator and the denominator of the
  density-weighted temperature now come from the same masked set of cells.
  Previously the numerator used every cell while the denominator was filtered,
  inflating T by roughly `colden_total / colden_filtered`.
- **`get_velocity` and `get_dens_weighted_density`** raise `NotImplementedError`
  under a filter — they have the same numerator/denominator mismatch and are not
  used by this pipeline; failing loudly beats returning a wrong number.
- Assorted robustness fixes: `filter_mode` validated at construction, MPI
  combined with a filter rejected, `cofm is None` checked before use.

With `filter_mode="None"` the fork reproduces upstream exactly.
